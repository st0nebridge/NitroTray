# Decisions

Settled architectural choices and standing constraints. Read before changing an area listed here;
supersede entries rather than editing them.

- [D-20260930-001] Rust backend + WebView2 (wry/tao) UI, tray via `tray-icon` — the specification allows it and HTML/CSS/SVG is the only route to match the reference popup's glows, gradients and rings (status: active)
- [D-20260930-002] Acer control path is the `AcerGamingFunction` WMI class (root\WMI, `ACPI\PNP0C14\APGe_0`) — it is what PSSvc wraps, it is documented by upstream Linux `acer-wmi` (AN515-58 quirk: predator_v4 + pwm), and encodings were verified on this machine; the PSSvc named pipe is native and undocumented and is not reverse engineered; no direct EC access (status: active)
- [D-20260930-003] WMI access requires elevation (Access denied as a normal user), so the tray runs as a normal user and a LocalSystem helper service (`NitroTrayService.exe`) exposes only typed commands over `\\.\pipe\NitroTray` (status: active)
- [D-20260930-004] Helper command set: get_capabilities, get_sensors, get_fan_state, get_performance_mode, set_fan_mode, set_performance_mode — get_sensors exists because temperatures and RPM are only readable elevated; no generic read/write bridge ever (status: active)
- [D-20260930-005] Performance mapping Quiet=0x00, Default=0x01, Performance=0x04 (verified: NitroSense `CurrentOperationMode`=4 matches firmware 0x04). Firmware also reports Turbo 0x05 as supported; it is shown as "other", never invented as a fourth popup mode (status: active)
- [D-20260930-006] `GetGamingFanSpeed` returns the stored custom set-point (reads 50 % in Auto, equal to NitroSense `CPUFanPercentage`), not live duty — the fan ring shows duty only when it is actually known (Max = 100 %, Custom = commanded) or calibrated from RPM measured in Max mode; never from a guessed maximum (status: active)
- [D-20260930-007] Custom fan curves run as a helper-side control loop, model-gated (AN515-58 verified), duty floor 20 %, full speed at ≥ 90 °C, fail-closed to Auto after 3 failed reads, on service stop, and on restart after a crash (marker file) (status: active)
- [D-20260930-008] Popup window uses DWM rounded corners, DWM border colour and native shadow rather than a transparent CSS-drawn frame — native flyout feel, no speech-bubble notch (status: active)
- [D-20260930-009] Cargo forbids `.` in binary names, so the specified `NitroTray.Service.exe` ships as `NitroTrayService.exe` (status: active)
- [D-20260930-010] NVML (vendor GPU API) is polled only while a UI surface is visible because it can wake the discrete GPU; tray graph icons use the Acer EC readings, which do not (status: active)
- [D-20260930-011] NitroTray never writes NitroSense's own registry state (`HKLM\SOFTWARE\OEM\NitroSense`); the tray always reads mode state back from firmware, so it stays truthful even if NitroSense's UI is stale (status: active)
- [D-20260930-012] Autostart truth is the HKCU Run value, written only when the user toggles it (settings / tray menu / installer) — the app never silently registers itself (status: active)
- [D-20260930-013] Popup typography follows the measured reference proportions (button labels ≈12 DIP, section titles ≈15, primary metric ≈29) rather than the specification's *suggested* sizes — the user asked to match the reference; 170/172 ink boxes match within ±1.5 DIP (status: active)
- [D-20260930-014] GPU temperature bands keep the specified defaults (80–89 °C red) even though the reference renders GPU 82 °C orange; thresholds are user-configurable in Settings › Telemetry (status: active)
- [D-20260930-015] Tray graph icons (user request, System Informer style): CPU = red temperature fill + cyan fan line, GPU = orange fill + green line, black background, 30–100 °C, fan scale auto = session peak ×1.1 (min 3000 RPM); icons are created app → GPU → CPU so they read CPU | GPU | app (status: active)
- [D-20260930-016] Coverage gate applies to the logic scope; event-loop/window glue is covered by live runs and render comparisons instead (waiver: quality/waivers/ui-glue.md) (status: active)
- [D-20260930-017] Promoting tray icons out of the Windows 11 overflow (NotifyIconSettings\IsPromoted) happens only when the user clicks "Show icons on taskbar"; never automatically (status: active)
- [D-20260930-018] WebView2 user data lives in %LOCALAPPDATA%\NitroTray\WebView2 (an installed exe folder may be read-only); UI assets are compiled into the exe and served with a strict CSP (status: active)
- [D-20260930-019] The LocalSystem helper binary is installed to and registered from `%ProgramFiles%\NitroTray` (admin-only); `install` copies itself there first — a service binary in the user-writable tray folder would be a user→SYSTEM escalation (status: active)
- [D-20260930-020] Hidden webviews are paused (controller hidden) and set to WebView2's low memory target; the popup is created that way. Measured idle CPU with the popup hidden: 2.318 % → 0.036 % of the machine (target < 0.2 %) (status: active)
- [D-20260930-021] Session-wide names (instance mutex, show/exit events) are scoped by NITROTRAY_INSTANCE; tests always use a unique tag and dev-run uses 'dev' (status: active)
- [D-20260930-022] Web UI goldens (tests/ui/fixtures/snapshots) lock the rendered markup and canvas draw logs; they are rewritten only with NITROTRAY_WRITE_FIXTURES=1 after the change has been reviewed visually (status: active)
- [D-20260930-023] Distribution is one NSIS setup (`src/installer/nitrotray.nsi`, built by `bin/package.ps1`) installing per machine into the fixed `%ProgramFiles%\NitroTray` (no directory choice, `/D=` ignored); components app / helper / autostart, upgrades keep the installed components and unticking removes one; the per-user `bin/install.ps1`/`uninstall.ps1` are retired (status: active)
- [D-20260930-024] SYSTEM-context code writes only to administrators-only locations: the helper's custom-curve marker is `%ProgramFiles%\NitroTray\curve-active`, never `%ProgramData%` (standard users can pre-create folders there and redirect writes); development helpers are exempt (status: active)
- [D-20260930-025] Source lives in the private GitHub repository `st0nebridge/NitroTray`; releases are `vX.Y.Z` tags on `main` carrying the setup exe and `SHA256SUMS.txt` (docs/release.md), published only after the elevated installer round trip passes; builds are unsigned until a signing certificate exists; if the repository goes public, only a flattened snapshot without process references is published (status: superseded by D-20261008-001)
- [D-20261001-001] `main` is kept release-clean: commits and tags as `Brandon Stonebridge <brandon@techster.co.uk>`, plain descriptive commit messages without workflow prefixes, only `vX.Y.Z` release tags, and no process-protocol labels in tracked files; the history was rewritten once on 2026-10-01 to reach this state (status: superseded by D-20261008-001)
- [D-20261001-002] The CPU/GPU graph icons show a hover flyout (rest 350 ms, hide on leave or click; single-click still toggles the popup). It shows embedded-controller readings only at the graph icons' cadence — hovering is not a "visible UI surface" for NVML (D-20260930-010) — never takes focus, is display-only, and replaces the icons' plain tooltip while Settings › Tray icons › Details on hover is on (status: active)
- [D-20261001-003] Webviews are created only while none of ours is on screen: the popup and flyout during start-up before the popup is first shown, later (re)creation deferred until popup, flyout and window are all hidden. Creating a WebView2 controller while another is visible never completed and hung the event loop (CU-20261001-003) (status: active)
- [D-20261001-004] The popup's horizontal layout follows one grid (16 DIP margins, two 264 DIP columns with a 12 DIP gutter, shared chevron lines, equal insets in both halves) and centres labels optically (cap height) and icons by ink instead of reproducing the reference image's own offsets; typography still follows the reference (D-20260930-013) (status: active)
- [D-20261008-001] Release route (owner's choice, 2026-10-08): `st0nebridge/NitroTray`'s `main` holds only release commits, each built from a commit of this development repository's `main` minus the paths `.release-scan` excludes (`bin/release-public.sh`), committed and tagged as `Brandon Stonebridge <brandon@techster.co.uk>` with a plain `NitroTray <version>: <summary>` message. The first (0.1.2) is a new root that replaces the earlier GitHub history and its v0.1.0/v0.1.1 tags and releases; later releases append. The development `main` is never pushed again. `CHANGES.md` and `DECISIONS.md` are published, scrubbed at the source; agent notes, the quality report, the release runbook and the Acer reference screenshot are not. Each release must pass the release scan (exit 0) over the tree, the new commits, the tag, the unpacked installer and the notes, with private words from a list kept outside every repository, and is built, tested and packaged from a `git archive` export; release builds remap build-machine paths. Replacing or pushing `main` happens only on explicit request; the repository stays private until the owner asks otherwise (status: active)
